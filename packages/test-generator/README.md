# @repro/test-generator

Turns a recorded Repro session into a Playwright test. The output is deterministic: the same session, expectations and test name always produce byte-identical code and the same source hash, so a regenerated test can be diffed and a stored one can be trusted.

The design is explained in [docs/TEST_GENERATION.md](../../docs/TEST_GENERATION.md). This file covers the package surface.

## Public interface

```ts
import { generatePlaywrightTest, chooseSelector, GENERATOR_VERSION } from '@repro/test-generator';

const output = await generatePlaywrightTest({
  session: { id, projectSlug, startedAt, initialUrl, release, browser, dashboardUrl },
  events,                                                   // RecordedEvent[] from @repro/contracts
  expectations: [{ kind: 'visible', testId: 'order-confirmation' }],
  testName: 'Checkout regression',                          // optional, derived when absent
  incident: { id, title, message },                         // optional, shown in the header
});

output.code;              // formatted TypeScript, ready to save as *.spec.ts
output.name;              // the test title
output.sourceHash;        // sha256 of the normalised input, see below
output.generatorVersion;  // GENERATOR_VERSION
output.selectors;         // one SelectorReportEntry per emitted or skipped interaction
output.omitted;           // OmittedEvent[]: every recorded event that did not become a step, with a reason
output.warnings;          // string[]: brittle selectors, skipped steps, ignored expectations
```

Types:

```ts
interface GeneratorInput {
  session: { id: string; projectSlug: string; startedAt: number; initialUrl: string; release?: string | null; browser?: string | null; dashboardUrl?: string | null };
  events: RecordedEvent[];
  expectations?: Expectation[];
  testName?: string;
  incident?: { id: string; title: string; message: string } | null;
}

interface SelectorReportEntry {
  seq: number;
  action: string;          // for example `fill "Card number"`
  strategy: 'testid' | 'role' | 'label' | 'placeholder' | 'attribute' | 'css' | 'none';
  selector: string;        // the locator expression, empty when strategy is `none`
  note?: string;           // why a weaker strategy was used, or why nothing was
}

interface GeneratorOutput {
  code: string; name: string; sourceHash: string; generatorVersion: string;
  selectors: SelectorReportEntry[]; omitted: OmittedEvent[]; warnings: string[];
}

function generatePlaywrightTest(input: GeneratorInput): Promise<GeneratorOutput>;
function chooseSelector(target: ElementDescriptor): { strategy: SelectorStrategy; code: string; note?: string };
```

`chooseSelector` is exported on its own so the dashboard can show, for any recorded element, which locator the generator would pick and why.

Smaller helpers are exported for the dashboard and for tests: `applyExpectations`, `hashNormalizedInput`, `canonicalJson`, `stringLiteral`, `regexEscape`, `commentText`, `describeAction`, `fixtureName`, `fixtureEnvVar`, `formatOffset`.

## What a generated test looks like

```ts
// Generated by Repro. Do not edit by hand; regenerate it from the session instead.
// Session: 3f1c2a9e-5b7d-4c8e-9a0b-1d2e3f4a5b6c
// Project: demo
// Recorded: 2025-09-09T06:40:00.000Z
// Release: 2026.09.1
// Browser: Chrome 140
// Incident: TypeError after Place order on /checkout
// Dashboard: http://localhost:3000/p/demo/sessions/3f1c2a9e-5b7d-4c8e-9a0b-1d2e3f4a5b6c
// Generator: @repro/test-generator 0.1.0
// Source hash: cd6f688b...
// Omitted events: 3 (each one is listed with its reason in the Repro dashboard)

import { test, expect } from '@playwright/test';

// Values Repro redacted at capture time are replaced by fixtures. Provide each one through
// the environment variable named in the comment next to its step.
const fixture = (name: string) =>
  process.env[`REPRO_FIXTURE_${name.replace(/([a-z0-9])([A-Z])/g, '$1_$2').toUpperCase()}`] ??
  `REDACTED_${name}`;

test('/login: click "Place order" completes', async ({ page }) => {
  const pageErrors: string[] = [];
  page.on('pageerror', (error) => pageErrors.push(String(error)));

  // Step 1 (00:00.000): navigate to /login
  // Recorded origin: https://shop.example.com
  await page.goto('/login');
  await expect(page.getByRole('textbox', { name: 'Email', exact: true })).toBeVisible();

  // Step 3 (00:03.900): fill "Password"
  await page.getByRole('textbox', { name: 'Password', exact: true }).fill(fixture('password')); // value redacted at capture; provide REPRO_FIXTURE_PASSWORD

  // Step 16 (00:21.900): click "Place order"
  // The recording shows POST /api/orders after this step; wait for it below.
  const responsePromise = page.waitForResponse(
    (response) =>
      new URL(response.url()).pathname === '/api/orders' && response.request().method() === 'POST',
  );
  await page.getByRole('button', { name: 'Place order', exact: true }).click();
  const response = await responsePromise;
  expect(response.ok(), 'POST /api/orders should succeed').toBeTruthy();

  // Success state. The recorded session failed here; a fixed build must reach it cleanly.
  await expect(page.getByTestId('order-confirmation')).toBeVisible();
  // Recorded error: TypeError: Cannot read properties of undefined (reading 'total')
  await page.waitForLoadState('networkidle');
  expect(pageErrors, 'the workflow should complete without uncaught errors').toEqual([]);
});
```

Paths are relative (`page.goto('/login')`) so the test runs against whatever `baseURL` the Playwright config points at. The recorded origin is kept in a comment.

## Secrets

The SDK masks sensitive controls before anything leaves the browser, so the generator never sees a card number or a password. A masked fill is emitted as `fixture('cardNumber')`, and the value comes from `REPRO_FIXTURE_CARD_NUMBER` at run time. When the variable is missing the test types `REDACTED_cardNumber`, which keeps the test runnable and makes the gap obvious in the failure.

The fixture name is derived from the control's `name`, `id`, `label`, `aria-label`, `placeholder` or accessible name, in that order, converted to camelCase (`card_number`, `Card number` and `cc-number` all become `cardNumber`; `cardNumber` becomes `REPRO_FIXTURE_CARD_NUMBER`). A control with no readable hint becomes `field<seq>`.

The test suite seeds `CANARY_` values into the masked fields of its fixtures and asserts they never appear anywhere in the output, even though the contract says those values are always null.

## Determinism and the source hash

`sourceHash` is the sha256 of the canonical JSON (sorted keys, no `undefined`) of:

```
{ generatorVersion, actions (normalised, without timestamps), expectations, testName, session.initialUrl }
```

Two recordings of the same clicks at different speeds have the same hash. Session id, release, browser, incident and dashboard URL only appear in the header comment and are not part of the hash. Bumping `GENERATOR_VERSION` changes every hash, which is how stored tests are known to be stale after an upgrade.

The code contains no clock reads and no randomness. The only timestamp is the recorded start in the header, and the only offsets are the recorded `mm:ss.mmm` values in step comments.

## Safety of the generated code

Every piece of recorded text that lands in the file goes through `stringLiteral`, `regexEscape` or `commentText`. Quotes, backslashes, newlines, U+2028, U+2029 and other control characters are escaped inside literals and replaced inside comments, so recorded text can never close a string, end a comment or become code. Backticks and `${` are inert inside the single-quoted literals the generator emits. `test/fixtures/injection.json` is a session made of breakout attempts; the tests assert that the output parses, that every payload survives as a literal, and that no `require`, `child_process`, `exit` or similar identifier appears as code.

Generation runs prettier last (`parser: typescript`, `singleQuote`, `semi`, `printWidth: 100`). Prettier throws on a syntax error, so a malformed emission fails loudly instead of producing a file that does not compile.

## Scripts

```bash
pnpm --filter @repro/test-generator build      # tsup, ESM + d.ts into dist/
pnpm --filter @repro/test-generator typecheck
pnpm --filter @repro/test-generator lint
pnpm --filter @repro/test-generator test       # vitest, fixture-based
```

Tests live in `test/`. `test/fixtures/*.json` are complete `GeneratorInput` documents validated against the contract schema on load: `checkout-broken` (the demo flow with masked payment fields), `enter-submit` (a form submitted with the Enter key), `no-stable-selector` (CSS fallback and an omitted click) and `injection` (hostile text everywhere a string can go).
